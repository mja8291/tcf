## 2. Architecture and key decisions (and why)

### Overall shape
Browser runs all survey logic and scoring; thin Vercel serverless route handlers do anything needing credentials. A service worker makes the app load and work with no network. Details are in the TRD; the decisions below are the ones a new session is most likely to break by accident.

### Offline-first is the central design constraint
Surveyors work with weak or no signal. Therefore:
- **IndexedDB `mqi-offline` v3** stores `schoolsCache`, `pendingSubmissions` (the sync queue), `drafts`.
- **Autosave** (`src/components/survey/SurveyTimerBar.tsx`): 2 s debounce, 12 s max wait, an immediate save when a `surveyId` first appears, and a flush on `pagehide`/`visibilitychange`.
- **Active-survey pointer** in localStorage (`ACTIVE_SURVEY_STORAGE_KEY` in `src/lib/survey-context.tsx`) plus a `hydrated` flag: every page that redirects "no survey" must wait for `hydrated`. The installed Android app always starts at `/`, and Android can kill the process, so Home has `AutoResumeRedirect` to jump back into the active survey.
- **Offline page changes are full page reloads.** Next's RSC fetch fails offline and falls back to a browser navigation, which wipes in-memory state. So all durable state must live in IndexedDB/localStorage, never memory only. Any new feature must respect this.
- `src/lib/draft.ts` keeps a `submittedSurveyIds` set and `discardSubmittedDraft` so the unload autosave flush can never resurrect a submitted survey as a draft (this was a real bug).
- **Service worker** `public/sw.js` with a build-generated precache manifest (`scripts/generate-sw-precache.mjs`, runs after `next build`, currently 18 pages + 32 assets). Install is failure-tolerant (`Promise.allSettled`), pages are network-first with cached fallback and `ignoreSearch`, static assets are cache-first, `/api/schools` and `/api/dashboard` network-first. `PwaBootstrap` asks the browser to check for a new worker on open/reconnect/foreground.
  - **Gotcha:** the precache "version" is a hash of the page and asset *lists*, not of code contents. A code-only change can leave it unchanged. Do not use it as the only proof a deploy picked up a change; inspect the live chunk instead.
  - New pages must be added to the page list in `scripts/generate-sw-precache.mjs` (this is how `/signin` and `/signup` got in).

### Google as the backend
- **Sheets auth:** Workload Identity Federation using Vercel's OIDC token (keyless), with fallback to an OAuth refresh token, then a service-account key.
- **Drive auth:** OAuth refresh token for a *human* Google account. A service account has no Drive storage quota on a personal "My Drive" folder, so it cannot create files there. History (see `~/.claude/projects/.../memory/oauth-token-expiry-recurring-issue.md`): uploads broke repeatedly because the consent screen was in Testing (7-day token expiry) and the personal account's quota was full. **Resolved 2026-09-06**: acting identity switched to `tcfengineeringdepartment@gmail.com` and the consent screen published out of Testing. If photo uploads start failing for everyone again, suspect an expired/revoked refresh token or full quota first.
- **Batched writes:** one Sheets append per tab per submission (`appendRowsByHeader`). Per-location/per-photo calls previously hit the serverless time limit and left half-written surveys. `/api/submit` has `maxDuration = 60`.
- **Header-name-based writes** (not positional): columns can be reordered in the sheet. Any column the app writes that a live tab lacks is auto-appended to the header row (`addMissingColumns`). The app never renames or removes columns.
- **Photos** are compressed on the device (long edge 1600 px, target under 300 KB) to stay far under Vercel's 4.5 MB request limit and to keep the offline store small. They upload one at a time to `/api/photos/upload` and the Drive link is written to the attachments tab. Failed uploads travel with a queued submission.

### Rubric and scoring
- Condition scores: Good/Ok/Poor/Very Poor = 100/75/50/25; N/A excluded (weight removed from numerator and denominator, i.e. renormalised).
- Division weights: Functionality 45, Safety 25, Aesthetics 30. Bands: >= 84 Excellent, >= 67 Good, >= 50 Average, else Poor.
- Across locations: **Safety groups take the worst (minimum)**, Functionality/Aesthetics take the **average**. Major/Minor scores split by whether the school maintains the item (`principalMaintained`).
- A fixed watchlist of 7 critical items, mapped to Method 2 groups via `METHOD2_CRITICAL_GROUP`.
- Two-button items: "OK/Unsafe" = 100/25; "Access to roof area /tanks" Available/Not Available = 100/25 and no N/A.
- Weights live in **one place** per method (`src/lib/data/method1-*`/`method2-items.ts`); scoring is `src/lib/scoring.ts`, shared by Review screen, submission and exports. Never inline weights elsewhere.
- **Rubric versioning (important):** every submission is stamped with `RUBRIC_VERSION` (`src/lib/data/rubric-version.ts`, currently `"2026-10-28"`) in a "Rubric Version" column. Superseded item lists are frozen as snapshots (`method1-legacy-items.ts`, `method2-legacy-items.ts`, `method2-v20261027-items.ts`, `-2-`, `-3-`) and `src/lib/export/find-survey.ts` picks the matching list so old surveys export with the weights they were scored under. **To change the rubric:** copy the current list to a new snapshot file, edit `method2-items.ts`, bump `RUBRIC_VERSION`, register the snapshot in `find-survey.ts`. Never edit a frozen snapshot.

### Two methods
- **Method 1** (whole campus: one score per item for the whole campus) and **Method 2** (by location: floor, location type, name; each scored separately, then rolled up). The choice screen at `/survey/method` shows both cards (`MethodCard.tsx`). Method 2 uses the latest "Method B" list (31 item groups).
- History worth knowing: Method 1 was briefly removed (commit `e258a90` made Method 2 the only method), then restored on the user's request (`f1ade96`) by reverting only the start-screen part. Do not remove Method 1 again unless asked.
- Review (last) page has "structural check" questions from a TCF Engineering slide (roof access type, overflow disposal, roof clean, rain spouts with photo-if-No, building-proximity risk factors, drilling check with slab-thickness assessment). **Recorded only, they never change a score.** They apply to both methods. Photos there use the normal upload/queue pipeline.

### Authentication (built, switched OFF in production)
- Email + password; accounts are rows in a **"Users"** sheet tab (header User ID, Created At, Name, Email, Password Hash, Approved); salted scrypt (N=16384, r=8, p=1); HMAC-signed HttpOnly `mqi_session` cookie valid 60 days. Sign-up creates a *pending* account; an admin sets `Approved` to YES in the sheet. No email service exists, so **there is no password reset** (delete the row, user signs up again, approve the new row).
- **Feature flag:** active only when `AUTH_SECRET` (>= 16 chars) is set. **It is currently NOT set in Vercel Production**, so sign-in is off (`/api/auth/config` returns `{"enabled":false}`). Deploying the code cannot lock anyone out; that was deliberate.
- Server enforcement: `requireUser()` (in `src/lib/auth/server.ts`) is the first statement in `/api/submit`, `/api/photos/upload`, `/api/dashboard`, `/api/export/*`. `/api/schools` stays public so it can be cached before sign-in. The submitter's name/email is stamped server-side from the session ("Submitted By", "Submitter Email" columns).
- Client (`src/lib/auth/client.tsx`): remembers the user in localStorage; offline-tolerant (only a clear 401/403 signs out, never a slow/failed request); a 401 during sync leaves surveys queued and asks for sign-in. Rotating `AUTH_SECRET` signs everyone out (queued data survives). Failed-attempt throttling is per server instance only.

### Home: Queue tab and Save and exit
- Home has Start / Queue tabs (`src/components/home/HomeTabs.tsx`, `QueueTab.tsx`, `useQueue.ts`) with a badge for drafts + queued surveys. Queue shows "In progress" drafts (Resume/Discard) and "Waiting to sync" surveys with status and Sync now.
- **Save and exit** (the logout-arrow icon in `SurveyTimerBar`): pauses the timer, saves the draft, calls `clearActiveSurveyPointers()` (exported from `survey-context.tsx`), then `window.location.assign("/?tab=queue")`. It must be a hard load, not `router.push` + `reset()`: that raced the page guards and landed on `/survey/find-school`. Without clearing the pointer, Home would auto-resume straight back into the survey.

### "Force app update" switch for the legacy v1 app (newest work)
- **Why:** the Play Store app (`app.web.mqi_app_tcf.pk`) will next open a new **v2 app at `https://tcfmqi.web.app`**. v1 stays live on Vercel as a legacy app. Phones must be pushed to update from the Play Store.
- Files: `src/lib/force-update.ts` (pure detection), `src/components/ForceUpdateGate.tsx` (wrapper, mounted outermost in `src/app/layout.tsx`), tests `src/lib/force-update.test.ts` and `src/components/ForceUpdateGate.test.tsx`.
- Behaviour when `NEXT_PUBLIC_FORCE_APP_UPDATE === "1"` **at build time**: inside the Android app (referrer starts `android-app://app.web.mqi_app_tcf.pk`, persisted to localStorage `mqi-in-android-app`; or standalone display mode + Android UA) a full-screen non-dismissable "Update required" screen with an "Update now" link to `https://play.google.com/store/apps/details?id=app.web.mqi_app_tcf.pk`; in a normal browser a dismissible banner pointing to `https://tcfmqi.web.app` (dismissal in sessionStorage `mqi-update-banner-dismissed`). The app renders underneath, `inert`, so background sync still runs and no local data is touched. Off: renders only children.
- **`public/.well-known/assetlinks.json` must stay exactly as is** (TWA verification). Never touch it.
- **State right now: the switch is ON in production.** The user ran `npx.cmd vercel env add NEXT_PUBLIC_FORCE_APP_UPDATE production` (value `1`, non-sensitive) and redeployed (deployment `mqi-survey-ld98fr2js-mja4.vercel.app`). I confirmed the live chunk has `enabled` defaulting to true. **Not yet confirmed on a real Android phone**; the user's last report (before turning it on) was "Android App doesn't show notification", which was because it was off. If it still does not show after a full close/reopen, investigate how the TWA launches (referrer may be absent; standalone + Android UA fallback should still catch it; check the service worker is not serving an old cached shell).
- To turn it off: `npx.cmd vercel env rm NEXT_PUBLIC_FORCE_APP_UPDATE production --yes` then redeploy (it is baked in at build time).

## 6. Known bugs and gotchas

- **Lint:** `npm run lint` reports 14 problems (13 errors, 1 warning), **all pre-existing** in `src/app/privacy/page.tsx`, `src/app/terms/page.tsx`, `src/components/survey/SurveyTimerBar.tsx:67` (`stateRef.current = state` in render) and `src/lib/survey-context.tsx:606` (set-state-in-effect). Not from recent changes; left untouched. Lint is not part of the build. Keep new code lint-clean (verify with `npx eslint <files>`).
- **`NEXT_PUBLIC_*` env vars are inlined at build time.** Changing one in Vercel does nothing until redeploy.
- **Precache version hash does not change on code-only changes** (see section 2).
- **Offline multi-page tests:** each page change is a hard reload, so a single script spanning pages offline fails ("Illegal invocation"). Test page by page. To test real offline, kill the local server process; the browser "offline" toggle does not reproduce the framework's RSC failures.
- **`USER_ENTERED` value input mode** on Sheets writes: a typed value starting with `=` could be treated as a formula. Acceptable while only approved staff submit; switch to `RAW` if untrusted users ever submit.
- **Mid-survey rubric change:** surveys in progress keep old scores but show newly added groups as unscored; affected locations must be reopened.
- **Brute-force limiter is per server instance** (in-memory). Not a global lockout.
- **Local data is unencrypted** in the browser (drafts, queue, photos). Sign-out warns but does not delete it.
- **Vercel CLI login can expire** ("invalid token"): the user runs `npx vercel login`.
- **Vercel build hiccup seen once:** `next/font/google` failed in Vercel's build with `Can't resolve '@vercel/turbopack-next/internal/font/google/font'` ("queries have exactly one entry"). Fixed by self-hosting the font. If the Vercel build breaks again on fonts, do not re-add `next/font/google`.
- **The Bash tool** mishandles some heredocs containing `'` inside large blocks; use the Write tool for file contents. Git warns "LF will be replaced by CRLF": harmless.
- **No Python, LibreOffice or Poppler on this machine:** `.docx` cannot be rendered to PDF/images for visual checks here; only structural checks are possible. `docx` is not preinstalled either (it was installed into the old scratchpad).
